## Surviving source defect and bounded repair

The initial PR #10 opt-in check required an operation ID for both arms but an evidence readback reference **only for ACTIVE observations**. Yet both BASELINE and ACTIVE outcomes determine the rate comparison. A malicious or mistaken caller could claim five baseline failures with no baseline result readback and five well-documented active successes.

The revised optional check now requires:
- a bounded subject and nonempty unique `operation_id` for every observation;
- nonempty `verification_evidence_ref` for **every BASELINE and ACTIVE observation**;
- nonempty `effect_digest` for ACTIVE observations (no corrected effect is presumed in BASELINE);
- the same exact correction subject and promotion/binding checks already required by the prior runtime.

The public default remains observational and backwards-compatible. Even with all fields populated, a fabricated reference can pass because this module **does not authenticate external evidence**. The source return state is still only `IMPROVEMENT_OBSERVED` for supplied rates. It does NOT issue `CAUSAL_LEARNING_QUALIFIED`.

**New regression:** Five baseline observations with distinct operation IDs but no baseline evidence refs, plus five active observations with populated effect/readback refs, must still yield legacy observed-rate improvement by default but must be rejected by the opt-in mode. Existing positive opt-in fixtures now include baseline readbacks, and missing baseline reference is a negative control.
